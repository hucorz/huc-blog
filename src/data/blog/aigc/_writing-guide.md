# AIGC 理论学习笔记写作规范

这份规范用于 `src/data/blog/aigc/**` 下的理论学习笔记。文件以下划线开头，不作为博客文章发布。

文中出现的术语和写法示例只用于说明判断方式，不代表每篇笔记都必须包含对应内容。

## 读者与目标

- 作者是一名 AIGC 工程师，熟悉模型的用途和常见工程流程，但底层数学与理论并不扎实。
- 笔记用于复习理论、补齐推导和衔接后续论文，不需要从“什么是 AIGC”开始教学。
- 默认读者理解当前主题中的常用概念和工程流程，但未必能跟上被省略的数学步骤。
- 最终目标不是最短，而是让理论基础一般的自己在一段时间后重新阅读，仍能顺着上下文完整理解。

## 开头怎么写

如果笔记来自一篇文章或论文，正文开头直接给出来源：

```md
> [文章或论文标题](链接) —— 作者
```

- 页面已经显示 frontmatter 中的标题，正文不要重复写一级标题。
- 不写“本文不介绍什么”“适合哪些读者”“下面记录几点”等宣言式开场。
- 默认不添加 TL;DR、阅读目标和内容清单。
- 不复述与理论主线无关的时代背景、发展历史或引入故事。

## 开始前先读完整来源

- 写来源型笔记前，先完整浏览原文，再决定结构；不要只抽取公式所在的段落。
- 阅读时分别标记：理论主线、关键公式、自然问题、设计动机、适用条件、超参数解释和其他方法的关联。
- 初稿完成后再对照一次原文，检查是否因为压缩而误删了负责解释“为什么”的好内容。
- 不要求保留原文顺序，但改写后的顺序必须比原文更容易跟随，不能破坏定义和推导的依赖关系。

## 哪些内容应该保留

### 理论主线

- 当前要解决的问题，以及它为什么会从上一节自然出现。
- 核心定义、模型公式、训练目标和采样公式。
- 推导依赖的条件，例如分布假设、独立性、约束关系、归纳假设和近似条件。
- 关键中间步骤。只要省略后需要读者自己猜用了什么条件，就应该写出来。
- 结论在训练、生成或实现中的实际作用。

### 帮助理解的补充

以下内容即使不是推导的必要步骤，只要能建立完整理解，也应该保留：

- 原文对“为什么这样设计”的准确解释。
- 自然会产生的关键问题及其答案。
- 公式成立的适用条件、边界和被忽略的权重。
- 如果当前记号与原论文或常见资料不同，保留必要的记号换算。
- 如果某种对比能直接帮助理解，保留与已有方法、工程现象或相关概念之间的关联。
- 如果原文讨论了超参数或工程设置，优先保留其理论原因，而不只是最终数值。
- 原文中简洁而准确的直觉说明，尤其是能够直接解释某项设计选择的内容。

保留这些内容时应融入当前推导，不要把原文中所有旁支原样搬过来。

## 哪些内容通常不用写

- 与笔记目标无关的背景介绍、历史回顾和“新的起点”一类开场。
- 已经理解且不会影响后续推导的基础概念科普。
- 反复使用的同一个比喻或对同一结论的多次总结。
- 只起活跃气氛作用的修辞、口号和面向读者的客套话。
- 与主线无关、后文也不会使用的公式、变量和拓展话题。
- 为了显得完整而复制的整段原文。
- 文章末尾机械重复正文的总结；如果“容易混淆的地方”确实能帮助复习，可以保留。

判断标准不是“它是不是主公式”，而是“删掉以后，设计动机、推导条件或与已有知识的联系是否会断掉”。

## 叙述顺序

一个新的推导阶段通常按下面的顺序展开：

1. 承接上一节留下的问题。
2. 说明接下来要解决什么，以及为什么需要这一步。
3. 引入所需变量和已知条件。
4. 展开关键推导。
5. 解释结论的含义和用途。
6. 自然引出下一节。

不要直接以一组新变量或长公式开始章节。特别要注意：

- 符号表只用于查阅，不能代替正文中的首次引入。变量第一次参与推理时，仍要说明为什么需要它、它代表什么。
- 问题、标题和解释不能提前使用尚未定义的符号。
- 临时变量较多时，先给简短映射表，然后立刻把原来的 loss 或关键公式用新变量重写，让后续推导继续连接原问题。
- 定义、结论和证明的顺序不能颠倒。不要先使用待证明的关系，再在后面补充它为什么成立。
- 压缩某一节后必须重新顺读前后章节，不能只检查被修改的局部段落。

## 问题与引用块

可以用引用块记录理解链条中的关键问题：

```md
> 已知每一步都有……，为什么累计后仍然有……？
```

- 直接写问题，不添加“我的疑问”“问题”等标签。
- 问题中的变量必须已经出现并得到解释。
- 问题后紧接回答，不要把答案分散到很远的位置。
- 只记录真正会卡住理解链条的问题，不把每个细节都改成问答。

## 公式怎么写

### 行内与行间

- 简单定义、短等式和非重点关系优先使用行内公式。
- 核心模型公式、多行推导、需要反复定位的公式使用行间公式。
- 不按公式长短机械压缩；理解上需要停下来看的公式，即使很短也可以单独成行。

### 编号与引用

- 后文需要引用的重要行间公式使用 `\label{eq:...}`，模板会自动编号。
- 正文使用 `\eqref{eq:...}` 生成可点击引用，不手写“上式”或容易失效的编号。
- 不给后文不会再使用的公式强行编号。

```md
$$
x_t=\alpha_t x_{t-1}+\beta_t\varepsilon_t.
\label{eq:forward-step}
$$

由公式 \eqref{eq:forward-step} 可以反解出……
```

### 必要的重复与改写

- 默认使用引用回看前面的公式，不无意义地复制同一公式。
- 当推导进入新阶段，读者需要看到“当前 loss 已经变成什么”时，可以在局部重新写一遍。
- 更推荐把前面的公式代入新定义或临时变量后改写，而不是原样复制。改写后的公式应直接显示“当前输入、预测目标或 loss 已经变成什么”。
- 重写后说明“这里只是换记号”“这里做了分布替换”或“这里忽略了只依赖时间步的权重”，避免读者误判等价关系。

### 数学表达必须说明的区别

当推导涉及下列概念时，需要明确说明对应区别；不相关的笔记不必刻意加入：

- 严格相等与仅分布相同。
- 代数等价与去掉常数或时间步权重后的训练简化。
- 边缘分布相同与联合分布、相关性相同。
- 一个变量出现在输入中与能够从输入中唯一恢复该变量。

少用“显然”“容易得到”“不难发现”。如果当前读者未必能立即看出，就写出关键中间式。

## 标题层级

- 二级标题表示理论主线中的阶段，一篇笔记通常使用 4～7 个。
- 三级标题只用于一个阶段中确实不同的子问题；能用自然段或加粗短句承接时，不再增加标题。
- 默认不使用四级标题。
- 不把每一步推导、每个问题和每条注意事项都做成标题。
- 标题以自然语言为主；当变量能明确表示输入、输出或推导对象时，可以加入简短行内公式，例如“从 $x_t$ 重建 $x_{t-1}$”。
- 不在标题中放完整等式或一串尚未解释的新变量。

## 语言与格式

- 使用个人学习笔记的语气，直接、克制，不写成论文翻译或完整课程讲义。
- 使用工程师熟悉的常用术语，不要为了统一中文而生硬翻译已经约定俗成的英文表达。例如当前领域普遍使用某个英文术语时，可以直接保留。
- 保留必要的直觉解释，但不要反复使用同一个类比。
- 加粗只用于局部引导，不连续堆叠；引用块主要用于来源和关键问题。
- 列表用于并列条件、变量映射、训练步骤或易混淆点，不把连续推导强行拆成列表。
- 表格只在记号对照、变量映射或比较关系明显更清楚时使用。
- 不使用水平分隔线切碎连续内容。

## 完成前检查

### 内容检查

1. 是否只保留了必要的来源开头，没有宣言式废话？
2. 是否保留了原文中真正有助于理解的动机、问题、补充条件和方法关联？
3. 是否误删了看似旁支、实际负责解释“为什么”的内容？
4. 是否加入了与主线无关的背景、重复类比或机械总结？

### 连贯性检查

1. 每一节是否承接了上一节的问题？
2. 每个符号在正文首次使用前是否得到解释？不能只依赖开头的符号表。
3. 问题和标题中是否出现了尚未定义的变量？
4. 临时变量引入后，是否马上与原 loss 或核心公式重新连接？
5. 结论依赖的条件是否在使用前写明？
6. 压缩以后是否从头到尾重新顺读，而不是只看修改片段？

### 公式与页面检查

1. 简单公式是否占用了不必要的整行空间？关键公式是否又被压得难以定位？
2. 公式的相等、分布等价、独立性、相关性和被忽略权重是否表述准确？
3. 关键公式是否有标签，引用是否指向正确编号？
4. 正文是否残留 `\label`、`\eqref` 等未渲染命令？
5. 正文标题和右侧大纲中的公式是否都正常渲染？
6. 修改后是否通过格式检查、公式检查和完整构建，并在浏览器中实际查看页面？
